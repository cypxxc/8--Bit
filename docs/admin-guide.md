# 8bit หลังบ้าน

เข้า `/admin` แล้วเข้าสู่ระบบด้วยบัญชีเจ้าของร้านที่ได้รับสิทธิ์ ข้อมูลลูกค้าไม่ได้เปิดผ่าน Supabase ให้ผู้เข้าชมเว็บหรือผู้สมัครสมาชิกทั่วไป

## การใช้งาน

หลังบ้านใช้เมนูด้านซ้ายสำหรับงานบริการ แชตลูกค้า บริการและราคา และประวัติแจ้งเตือน เมนูที่เลือกมีสีไฮไลต์ บนมือถือกดปุ่ม “เมนู” ด้านบนเพื่อเปิดแถบเมนู เลือกหน้าแล้วเมนูจะปิดเอง หรือปิดด้วยปุ่มกากบาท/ปุ่ม Escape ได้ การ์ดสรุปสถานะงานแสดงเฉพาะหน้างานบริการ

- **งานบริการ**: ค้นหาด้วยชื่อ เบอร์โทร หรือเลขงาน กรองสถานะ เปิดรายการเพื่อแก้สถานะ รุ่นเครื่อง อุปกรณ์ที่ฝาก ราคา และหมายเหตุภายใน
- **เพิ่มงานหน้าร้าน**: เลือกบริการและกรอกข้อมูลติดต่อ หลังบันทึกเปิดรายการเพื่อเพิ่มรายละเอียด ไม่ส่ง LINE โดยอัตโนมัติสำหรับงานที่เจ้าของร้านเพิ่มเอง
- **บริการและราคา**: แก้ชื่อ รายละเอียด ราคาเริ่มต้น หรือปิดรับบริการ เว้นราคาไว้เพื่อแสดง “สอบถามราคา” การปิดบริการไม่มีผลกับประวัติงานที่รับไว้แล้ว
- **ประวัติแจ้งเตือน LINE**: รายการจากเว็บถูกบันทึกก่อนส่ง LINE ถ้าส่งไม่สำเร็จหรือผลไม่แน่ชัดสามารถกดส่งใหม่ ระบบใช้ retry key เดิมเพื่อป้องกันซ้ำในช่วงที่ LINE รองรับ เมื่อ LINE รับคำขอแล้วจะไม่ส่งซ้ำ ส่วนผลที่ไม่แน่ชัดเกิน 23 ชั่วโมงต้องตรวจแชตเอง
- **แชตลูกค้า LINE**: อ่านข้อความเข้าในเว็บ แยกห้องด้วยบัญชี LINE ของลูกค้า ค้นหาชื่อ/รหัสบัญชี กรองยังไม่อ่าน และเปิดประวัติก่อนหน้าได้ครั้งละ 50 ข้อความ อัปเดตทุก 5 วินาทีขณะเปิดหน้าแชต การตอบยังใช้ LINE OA Manager
- ถ้าบันทึกแล้วแจ้งว่ารายการถูกแก้ไข ให้ปิดรายละเอียด กดรีเฟรช แล้วเปิดรายการล่าสุด ป้องกันการเขียนทับข้อมูลจากอีกหน้าต่าง

## ตั้งค่าบัญชีเจ้าของร้าน

ใช้เครื่องที่ถือคีย์หลังบ้านและมีสิทธิ์ดูแลโปรเจกต์เท่านั้น:

```powershell
npx tsx scripts/provision-owner.ts owner@example.com
```

คำสั่งเตรียมบริการเริ่มต้นเฉพาะรายการที่ยังไม่มี เพิ่มสิทธิ์เจ้าของร้านให้บัญชีอีเมลที่ระบุ และสร้างลิงก์ตั้งรหัสผ่านแบบใช้ครั้งเดียวใน `.env.owner-setup` โดยไม่ส่งอีเมล เปิดลิงก์นี้ในเบราว์เซอร์และตั้งรหัสผ่านอย่างน้อย 12 ตัวอักษร ไฟล์นี้ถูกยกเว้นจาก Git ไม่ควรส่งลิงก์ให้บุคคลอื่น ถ้าหมดอายุให้เรียกคำสั่งเดิมเพื่อสร้างใหม่

## ก่อนนำขึ้นเว็บไซต์จริง

ตั้งค่าบนโฮสต์: `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_SECRET_KEY`, `LINE_CHANNEL_ACCESS_TOKEN`, `LINE_ADMIN_USER_ID` โดย secret และ LINE token ใช้เฉพาะฝั่งเซิร์ฟเวอร์ ไฟล์ `.env.local` ไม่ถูกส่งขึ้นโฮสต์โดยอัตโนมัติ ใช้ HTTPS และกำหนดค่า Supabase Auth URL ตามโดเมนจริง

Rate limit ใช้ฐานข้อมูลร่วมกัน ไม่ใช่หน่วยความจำของเซิร์ฟเวอร์ โดยโฮสต์ต้องกำหนด `x-forwarded-for` จาก IP จริงและเขียนทับค่าที่ผู้ใช้ส่งเข้ามาเอง

ตารางทั้งหมดเปิด RLS และไม่ grant สิทธิ์ให้ anon/authenticated การอ่านรายการบริการสาธารณะผ่าน `/api/services` คืนเฉพาะรายการที่เปิดรับและไม่รวมข้อมูลลูกค้า ตารางภายในไม่มี RLS policies โดยตั้งใจเพราะเข้าถึงผ่านเซิร์ฟเวอร์ที่ตรวจ `shop_admins` เท่านั้น ([คำอธิบาย Supabase](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy))

Supabase แจ้งว่าการตรวจรหัสผ่านที่เคยรั่วไหลยังปิดอยู่ในโปรเจกต์ ควรเปิดเมื่อแผนบริการรองรับ ([คู่มือ](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection))

## การตรวจสอบ

```powershell
npx tsx --test tests/validation.test.ts
npm run build
```

การทดสอบ integration ใน `tests/backend-integration.ts` ต้องใช้เซิร์ฟเวอร์ทดสอบพอร์ต 3004 ที่ตั้ง LINE token/recipient เป็นช่องว่างเพื่อไม่ส่งข้อความจริงเท่านั้น สคริปต์สร้างบัญชีและข้อมูลชั่วคราวในฐานข้อมูล และบันทึกรายการสิ่งที่ต้องล้างใน `.env.backend-test` หลังตรวจหน้าจอให้เรียก `npx tsx tests/cleanup-backend.ts` เสมอ ห้ามใช้กับโปรเจกต์อื่นโดยไม่ตรวจค่าการเชื่อมต่อ

ยังไม่ได้ deploy เว็บจากงานนี้ ข้อมูลหน้าร้าน เช่น เบอร์โทร ที่อยู่ และเวลาทำการใน `lib/config.ts` ยังต้องยืนยันก่อนเผยแพร่

## ตัวรับแชต LINE ที่เปิดใช้งานแล้ว

LINE OA `@356qitzh` เชื่อม Webhook ไปยัง `https://miohhudxbixsydpurdoi.supabase.co/functions/v1/line-webhook` บน Supabase 8bit เปิด Use webhook และ Webhook redelivery แล้ว ตัวรับนี้ทำงานโดยไม่ต้องเปิดคอมร้าน ส่วนหน้าเว็บหลังบ้านยังรันในเครื่อง

Edge Function ใช้ `LINE_CHANNEL_SECRET` ตรวจ HMAC SHA-256 จากข้อมูลดิบ และ `LINE_BOT_USER_ID` ตรวจบัญชีปลายทางก่อนบันทึก โดยเก็บค่าทั้งสองใน Edge Function Secrets และ `.env.local` ไม่มีคีย์ฝังในโค้ด ตั้ง `verify_jwt=false` เฉพาะตัวรับนี้ เพราะ LINE ใช้ลายเซ็นของตนเอง

โค้ดต้นฉบับตัวรับคือ `lib/line/webhook.ts` ก่อน deploy ต้องคัดลอกไฟล์นี้ไป `supabase/functions/line-webhook/webhook.ts` และส่ง `index.ts`, `webhook.ts`, `deno.json` ไปด้วย ตารางแชตทั้งหมดปิดการเข้าถึงโดยตรงจาก anon/authenticated; API อ่านห้อง อ่านไฟล์ และทำเครื่องหมายอ่านแล้วตรวจสิทธิ์เจ้าของร้านทุกครั้ง

รองรับแชตส่วนตัวเข้าจากลูกค้า: ข้อความ, รูปภาพ และลิงก์เปิดไฟล์/เสียง/วิดีโอ ส่วนสติกเกอร์กับตำแหน่งแสดงชนิดหรือรายละเอียด ไม่มีการดึงแชตเก่าย้อนหลังหรือข้อความที่ร้านส่งจาก OA Manager และไม่รับแชตกลุ่ม รูป/ไฟล์โหลดจาก LINE เมื่อเปิดดู จึงอาจหมดอายุตาม LINE และไม่ได้เก็บสำเนาถาวรไว้ ลูกค้ายกเลิกส่งแล้วระบบล้างเนื้อหาข้อความและหยุดเปิดไฟล์ แม้ได้รับข้อความเดิมซ้ำภายหลัง

การทดสอบ: `npx tsx --test tests/line-webhook.test.ts` และ `npx tsx tests/line-integration.ts` (เซิร์ฟเวอร์ทดสอบพอร์ต 3004) สคริปต์หลังส่งเหตุการณ์จำลองที่มีลายเซ็นไปตัวรับจริง สร้างลูกค้าทดสอบและบัญชีทดสอบชั่วคราว ไม่ส่งข้อความออกไปหาใคร ปกติล้างข้อมูลในท้ายการทดสอบ ถ้าใช้ `--keep` เพื่อตรวจหน้าจอ ให้เรียก `npx tsx tests/line-integration.ts --cleanup` เมื่อเสร็จ
